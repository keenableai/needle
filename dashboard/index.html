Slices

freshstream

Fresh, time-sensitive queries mined hourly from RSS feeds and Google Trends, scored on ranking quality (RBP@5) by an LLM relevance judge.

freshstream — RBP@5

20 fresh queries per run, mean RBP over all queries in each 6-hour window; the hairline marks the metric ceiling

rarestream

Rare-entity queries mined from real search logs — obscure names, technical terms, and long compounds selected by tokenizer difficulty. Scored on ranking quality (RBP@5) by the same LLM relevance judge as freshstream.

rarestream — RBP@5

100 rare-entity queries per daily run; the hairline marks the metric ceiling

companyfill

Company & financial fact-lookups: registry-grounded facts (CEO, HQ, founding year…), quarterly SEC-XBRL facts (filings), and known-item SEC-filing retrieval by accession identity (filingdoc). Companies mixed across cap tiers; ~half the filings/filingdoc queries carry operator syntax ("quoted", site:, date filters). Uniform deterministic answer-recall@5 with an LLM-judge backstop.

scholar

Known-item paper retrieval: find a specific paper by its title vs. by a full-text-only detail. Deterministic match on the paper's arXiv / DOI / PMID.

legal

Known-item legal retrieval: find a specific court opinion by its caption, or a specific CFR section from its substance. Roughly half the queries carry operator syntax ("quoted", site:, date filters). Deterministic match on citation / docket / URL identity.

legal — caselaw recall@5

federal court opinions found by caption-style queries

legal — code recall@5

CFR sections found from their regulatory substance

findallmcp

Distribution questions — exhaustive enumerations ("find all X") and population statistics ("what fraction of X") — answered by an LLM agent driving one MCP search backend at a time under a hard dollar budget. Gold is computed from structured public registries (Show HN via Algolia, SEC EDGAR full-text search), so an agent reasoning from priors or a few top documents scores measurably worse than one that holds the population. A backend's score is the mean per-query score across both buckets: an enumerate query scores the share of the gold set it covers, a stat query scores 1 − relative error, floored at 0.

findallmcp — enumerate set recall

share of the gold population covered by the agent's answer

findallmcp — stat accuracy

1 − relative error of the agent's population statistic, floored at 0

Appendix — methodology & configuration

Everything below is pinned in keenableai/keenbench; the dashboard only aggregates published run data, and every number on this page can be recomputed from the archived artifacts (A4).

A1 — metric definitions

how every number on this page is computed (src/keenbench/shared/metrics.py and per-bench score.py)
metricbenchesdefinition
RBP@5freshstream, rarestream rank-biased precision with persistence p = 0.8: (1 − p) · Σ gain(rᵢ) · pⁱ⁻¹ over the top 5 results. Judge ratings map to gain 4 → 1.0, 3 → 0.667, 2 → 0.117, 1/0 → 0. The all-4s ceiling is 1 − 0.8⁵ = 0.672 (the hairline on RBP charts); scores are not normalized by it. A query is scored only if every one of its results was judged; otherwise it is dropped from the mean and counted as judge errors.
redundancy penaltyfreshstream, rarestream applied to ratings before RBP: a duplicate URL −4 rating steps, the 2nd result from the same domain −1, the 3rd and later −2, all floored at 0. Skipped when the query itself carries a site: operator. Raw and penalized ratings are both shown in the judgement browser.
answer-recall@5, MRR@5companyfill a query is a hit when the gold answer appears in a top-5 title or snippet — deterministic matcher, with an LLM-judge backstop for paraphrased answers. MRR is the mean reciprocal rank of the first hit.
recall@10, MRR@10scholar known-item: the gold paper identified in the top 10 by arXiv ID / DOI / PMID match.
recall@5, MRR@5legal known-item: the gold opinion or CFR section identified by citation / docket / URL match.
scorefindallmcp per query: an enumerate task scores recall of the gold entity set (name / alias / registrable-domain matching); a stat task scores max(0, 1 − |answer − gold| / |gold|). The reported score is the mean over all non-errored queries of both kinds; errored agent runs are excluded from the mean and reported as errors.
latency p50 / p95all percentiles over per-call durations of successful search API calls, pooled across queries in the window; runs published without per-call samples contribute their per-run percentiles instead. Failed calls carry no latency sample and show up in the error rate.

A2 — LLM judge

rates freshstream and rarestream results; companyfill uses it only as a fallback answer matcher — scholar, legal, and findallmcp are judged deterministically

Model: google/gemini-3-flash-preview via OpenRouter, temperature 0, one pointwise call per document. The exact model a run used is recorded as judge_model in its archived report and shown when you pick a run in the judgement browser, so judge swaps are visible in the history.

Blind to engine identity: the prompt contains the query, document title, URL, published date, and snippet — never the engine name. Results with the same URL from different engines are pooled and judged once per query (longest available snippet, first non-empty title and date), and that single judgement is reused for every engine that returned the URL, so an engine cannot gain from formatting the same page differently. Snippet quality still matters across distinct URLs — a judge preference for a snippet style would be a shared bias across engines; the per-result reasoning published with every run exists so this can be audited.

Rubric: 0–4 Needs Met scale (FailsM / SM / HM / FullyM) with hard gates for wrong entity, stale coverage of dated events, and search-operator compliance ("quoted phrases", site:). The full prompt is one template in the repo: src/keenbench/shared/prompts/judgement.jinja.

Known limitation: keenbench is operated by Keenable and there is no systematic human-agreement audit of the judge yet. What makes the numbers checkable in the meantime: the judge is blind and shared across engines, every rating ships with its reasoning, and queries, prompts, and raw results are all published — any rating can be independently re-scored.
