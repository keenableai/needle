\begin{abstract}
We propose \needle, a method and a live benchmark to compare web search
APIs for AI agents. An agent
sends such an API a text query and sees only the titles, URLs and
snippets it returns. Agent benchmarks score the final answer, so they
rarely test the search API alone. \needle scores the API response
directly. Hourly and daily runs build new queries from public sources
for news, finance, research papers and law, and add a fixed stream of
rare-word queries. We compare each engine with the ceiling: the best results that any
tested engine found. We run \needle for ten weeks on 26 search engines from 20 vendors. In a
12-day window with all engines, the benchmark orders 180 of the 210
pairs of main engines, and the best engine reaches only 73\% of the
ceiling. Title searches hide a large gap: most engines find a paper from
its title, but much less often from keywords in its body. The code, prompts, queries and per-query
results are public.
\end{abstract}

\section{Introduction}

An \textbf{AI agent} is a language model that works in steps: it calls
tools, reads their output and decides what to do next. Agents get facts
from the web through a \textbf{web search API}: a
service that takes a text query and returns a short ranked list of
results, each with a title, a URL and a snippet.

Many vendors sell such APIs, but a developer who must choose one has
little public evidence. Agent benchmarks score the final answer, which
mixes the search API with the model and the prompt. Testing the API alone is hard. The live web
has no fixed document list or full relevance labels, and fixed test sets
go stale and can leak into model training data
\citep{sainz2023trouble,balloccu2024leak}.

\needle tests the search step alone. Each run sends the same new queries
to every \textbf{engine}, which is one search API with fixed settings,
and scores the results that each engine returns. The queries come from
five tasks: news events, company finance facts, research papers, US law
and rare-word queries from agent logs.
When a query has a known answer, such as a paper's arXiv id, we check
whether the results contain it. Otherwise an LLM judge rates each result.
We compare each engine with the \textbf{ceiling}: the best results that
any tested engine found for that query.

We ran \needle for ten weeks on 26 engines from 20 vendors. Our
contributions:
\begin{itemize}[nosep,leftmargin=1.2em]
\item \textbf{A method to compare web search APIs.} \needle needs no
  fixed document list and no full relevance labels. It builds new queries
  for each run, scores each engine against the ceiling and tests which
  pairs of engines differ (Section~\ref{sec:bench}).
\item \textbf{A public live benchmark.} The code, prompts, queries and
  per-query results of every run are public.
\item \textbf{Three findings.} Most engine pairs have a clear winner
  (Table~\ref{tab:results}). Title searches hide large gaps between
  engines (Figure~\ref{fig:scholar}). One engine leads nine of ten
  weeks (Figure~\ref{fig:weekly}).
\end{itemize}

\section{Related Work}
\label{sec:related}

\textbf{Live and API benchmarks.} LiveBench and LiveSearchBench draw new
items from dated sources but score model answers
\citep{white2025livebench,zhou2026livesearchbench}. \needle scores the
search results behind such answers. BrowseComp scores agents end to end
\citep{wei2025browsecomp}. FreshStack and BrowseComp-Plus fix the corpus
to isolate retrieval \citep{thakur2025freshstack,chen2026browsecompplus},
while \needle keeps the live web. API comparisons use static questions
under one agent \citep{selvam2026search,aa2026searchindex}, and web
engine audits use fixed query sets
\citep{lewandowski2015evaluating,kirsten2026characterizing}. \needle
draws new queries each run and scores the API without an agent.

\textbf{Scorers and tasks.} LLM assessors and simulated known-item queries
can reproduce system rankings
\citep{thomas2024llms,upadhyay2025largescale,azzopardi2007simulated,he2025totelicitation}.
\needle uses both and checks its judge against models from other vendors.
Domain benchmarks cover literature, caselaw and finance search on fixed
sets \citep{ajith2024litsearch,hou2025clerc,hu2026finsearchcomp}, while
\needle runs these tasks on new queries each day. Full text helps
retrieval beyond abstracts \citep{lin2009fulltext}, and our body queries
test that gap live.

\section{The Benchmark}
\label{sec:bench}

We test 26 engines from 20 vendors. The 21 \textbf{main engines} are
one engine per vendor plus Brave's LLM-context endpoint. The other five
are mode variants, such as Exa Instant.

A \textbf{query-run} is one query issued in one run. We use three
windows in 2026: ten weeks, 31 August--8 November
(Figure~\ref{fig:weekly}), the \textbf{main window}, 17--28 October,
with the 276 runs in which all main engines took part
(Table~\ref{tab:results}), and 31 scholar runs, 29 September--28 October
(Figure~\ref{fig:scholar}). Table~\ref{tab:protocol} lists the tasks.

\subsection{Queries}

Table~\ref{tab:examples} gives example queries for each task.

\textbf{News.} Each hour an LLM writes 20 event queries from news feeds
and Google Trends, rejecting evergreen items.

\textbf{Finance.} \textbf{Fact} queries ask for company facts from
Wikidata \citep{vrandecic2014wikidata} and GLEIF, \textbf{money} queries
for quarterly 10-Q figures from SEC XBRL, and \textbf{filing} queries
for one SEC filing by description.

\textbf{Scholar.} Each recent arXiv or Europe PMC \citep{europepmc2015}
paper yields four paired known-item queries \citep{azzopardi2007simulated}:
its normalized \textbf{title}, \textbf{body keywords} for a detail absent
from title and abstract, a \textbf{body question} about that detail, and
a \textbf{tip-of-tongue} description \citep{arguello2021tot} without
names or exact values. All four must pass the filters.

\textbf{Legal.} CourtListener opinions yield caption queries, and eCFR
sections yield queries based on verbatim spans. Filters reject citation
leaks.

\textbf{Rare.} We sample a fixed public stream of English agent queries
containing rare words (\mbox{\citealp{ning2026agentic}}; \mbox{\citealp{li2026openresearcher}}; \mbox{\citealp{zhou2026lrat}}).

At least half of the legal queries and of the finance money and filing
queries carry a search operator: quotes, \texttt{site:}, \texttt{after:}
or \texttt{before:}. Where an API has a native filter for an operator,
the client uses it.

\subsection{Scores}
\label{sec:scoring}

\textbf{News and rare.} GPT-6 Luna at high reasoning effort rates each
distinct result from 0 to 4 using a shared query profile, with checks for
relevance, coverage, freshness and literal operator compliance. The scale
adapts the Needs Met levels of \citet{google2025sqrg}. Ratings 0--4 map
to gains $g=\{0,0,.117,.667,1\}$, which put high weight on strong
results \citep{kanoulas2009empirical}: one rating-4 result is worth more
than eight rating-2 results. The judge sees at most 2,000 snippet characters.

For each query, the ceiling keeps the best rating per normalized URL
across all engines, variants included, and sorts these ratings
\citep{sparckjones1975pool,zobel1998reliable}. With $r_i$ the rating at
rank $i$, we compute \ndcg \citep{jarvelin2002cumulated} as
\[
\mathrm{nDCG}_e(q)=\frac{1}{\mathrm{IDCG}(q)}\sum_{i=1}^{5}\frac{g(r_i)}{\log_2(i+1)}.
\]
IDCG is the same sum over the top five pooled ratings. Missing ranks contribute
zero. Repeated normalized URLs receive zero gain except on
\texttt{site:} queries. We drop a query-run from all engines if any
judgment fails or no result reaches rating 2. The task score is the mean
over retained query-runs.

\textbf{Scholar, legal and finance.} Recall@$k$ counts queries with a
matching result in the top $k$. Scholar matches arXiv ids, DOIs and
PMIDs. Legal matches citations, dockets and identifiers in URLs and
snippets. Caselaw recall measures case identity, not necessarily the
opinion page. Finance checks whether the snippets contain the answer,
with a 0.1\% money band and a 15\% headcount band. The ceiling is a hit
by any engine.

\subsection{Overall share and failures}
\label{sec:agg}

For task metric $M_t$, an engine's overall share is
\[
S(e)=\frac{1}{5}\sum_{t=1}^{5}
\frac{M_t(e)}{M_t(\mathrm{ceiling})}.
\]
The tasks have equal weight. The ceiling is the best the tested engines
found, not the best the web contains.

We exclude account-side failures (our quota, rate limit, login or
credit) on every task, and other failures score zero. The exclusions
remove up to 36\% of an engine's query-runs.

\paragraph{Comparing two engines.}
Some queries are hard for every engine, so intervals for single engines
can overlap even when one engine beats another on the same queries. We
therefore bootstrap the difference $S(a)-S(b)$. Within each task, we
resample whole runs 2,000 times, using the same runs for every engine
\citep{efron1993bootstrap}, and recompute the overall shares. Each
difference gets a normal-approximation interval with Bonferroni
correction for all $\binom{21}{2}=210$ pairs at a 5\% familywise level
\citep{carterette2012multiple}. An interval that excludes zero orders
that pair. The intervals measure sampling uncertainty, not scorer error.

\subsection{Judge validation}
\label{sec:validation}

We sample 100 news and 100 rare queries, with six distinct top-five URLs
per query (1,200 results). Four models judge them with the production
prompt, input and settings: GPT-6 Luna (the production judge), Claude
Opus 5.5, Gemini 4 Argon and Grok 4.7. We score each model against the
mean grade of the other three. GPT-6 Luna agrees with this leave-one-out
consensus at quadratic-weighted $\kappa=.89$
\citep{cohen1968weighted}, and the other three models at .91--.92. Its mean grade
of 1.59 is inside the 1.55--1.67 range of the others.

In a second check, Gemini and Grok grade the complete result pools of 100
queries (5,698 results from all 21 main engines) from snippets, with a
separate written guideline. The
engine ranking from each rater agrees with the ranking from the
production judge at Spearman .94. Neither rater separates Keenable from
Exa on this sample. Both checks measure model agreement, not human
validation.

\section{Results}
\label{sec:results}

\paragraph{Most engine pairs have a clear winner, but not all.}
For 180 of the 210 pairs of main engines, the adjusted interval for the
score difference excludes zero, so one engine scores reliably higher
than the other. Of these, 169 also hold
when we resample days instead of runs and when we keep only query-runs
with no account-side failure in any main engine. The other 30 pairs stay unordered, which does
not mean equal scores. No engine leads
every task (Table~\ref{tab:results}), so the overall lead depends on the
task mix. Keenable leads Exa by 4.6 points, and
scholar contributes 3.7 of them. With scholar dropped and the other four
tasks at equal weight, the lead is 1.1 points.

\paragraph{Title searches hide large gaps.}
An agent that follows up a detail it read elsewhere has no title to
search for. Over 31 scholar runs, all engines but Ceramic, DeepSeek and
Octen reach recall@10 .71--.98 from titles. The same 23 engines span
.08--.72 on body keywords (Figure~\ref{fig:scholar}), so title tests can overstate how well an
engine serves such an agent. Keenable leads at .72, followed by its
realtime mode (.71) and Kagi (.67).

\paragraph{Weekly rankings are stable, but not fixed.}
Adjacent weekly rankings agree at Kendall's $\tau_b$
\citep{kendall1945ties} .81--.94. Keenable leads nine of ten weeks. Perplexity
leads the week of 2 November by 0.5 points, inside the intervals
(Figure~\ref{fig:weekly}).

\section*{Limitations}

\paragraph{Conflict of interest.}
The authors' organization builds an evaluated engine. The code, prompts,
clients and per-query outputs are public so readers can audit the claims.
All engines receive the same queries, snippet cap, request pacing and
judge. Each keeps one setting throughout the main window. We cannot tell
whether a vendor changed its index for the benchmark or for other reasons.

\paragraph{Evidence and judge.}
Scores measure the API response, not the fetched page. Short snippets can
hide relevant content \citep{turpin2009summaries,kazai2022less}. News and rare depend on one LLM judge.
All audit raters are also LLMs, which cannot replace human validation
\citep{faggioli2023perspectives,clarke2025llmbased}. LLM judges can
reward query-term stuffing \citep{alaofi2024fooled} and favor some
vendors or their own outputs
\citep{balog2025rankers,soboroff2025dont,panickssery2024self}. The judge
shares a vendor with ChatGPT search, and some audit raters share one
with Claude search.

\paragraph{Matcher error.}
Identifier matching can miss a target page that lacks its id. Finance
table figures can match the wrong period when snippets omit column
headers. We bound this error only pooled over engines.

\paragraph{Coverage and weights.}
Queries are English and US-centric. Equal task weights do not estimate
agent traffic, and the lead depends strongly on scholar. Default API tiers
need not be each vendor's best. ChatGPT and Claude search return sources
through answer-generating tools, so their quality scores are comparable
but their latency and cost are not. The ceiling depends on the engine
pool \citep{buckley2007bias}, so compare shares only within a common
window.

\paragraph{Failures and timing.}
Excluding account-side failures assumes those requests would score like
the rest. Without that assumption, Claude search can take any rank from
3 to 20 and TinyFish from 11 to 20. Engines process
queries at different speeds, so slow engines see news later. A
five-minute dispatch filter leaves the news order unchanged.

\paragraph{Reproducibility.}
Public sources and queries permit tuning or special handling of benchmark
traffic. The archive holds the queries, reference answers, results and
judgments of the studied runs, but not each run's code revision.

\section{Query Filters}
\label{app:leak}

Scholar samples five domains (computer, physical, life, social and health
sciences) and three age bands (7 days, 30 days, 1 year), targeting seven
accepted papers per cell. Each paper must pass
all four filters:
\begin{itemize}[nosep,leftmargin=1.2em]
\item \textbf{Title:} at least four words, plus a digit, acronym,
  hyphenated term or five content tokens.
\item \textbf{Body keywords:} at least three words and two content
  tokens absent from title and abstract.
\item \textbf{Body question:} at least eight words and the same novelty
  test as body keywords.
\item \textbf{Tip-of-tongue:} at least twelve words and at most two
  content tokens shared with the title, with no quotes, decimal,
  five-digit number or coined title/abstract term.
\end{itemize}
One logged run accepts 323 of 572 candidate papers (56\%).
The effect of rejecting other papers on engine order is untested.

News draws from 124 feeds and Google Trends RSS for 52 US geographies.
Prompts reject evergreen items and request two-to-six-word event queries.
Legal captions come from 14 federal courts on CourtListener. CFR queries
contain one verbatim two-to-eight-word span but no citation or target
section number. Only the quoted variant retains quotation marks.
Rare queries must pass fastText English language ID
\citep{joulin2017bag,joulin2016fasttextzip} and contain a word split into
at least five BERT WordPieces \citep{wu2016gnmt,devlin2019bert}.

\paragraph{Paired intervals.}
The main window has 12 scholar, 232 news, 10 finance, 12 rare and 10 legal
runs. For pair $(a,b)$, let $\widehat{\Delta}_{ab}=S(a)-S(b)$ and let
$s_{ab}$ be the standard deviation of its 2,000 bootstrap differences.
The adjusted interval is $\widehat{\Delta}_{ab}\pm z\,s_{ab}$ with
$z=3.68$, the two-sided Bonferroni value for 210 comparisons at
familywise level .05. The single-engine intervals in
Table~\ref{tab:results} instead use the 2.5th and 97.5th bootstrap
percentiles. Their overlap is not a test of the difference between two
engines.

\paragraph{Dependence and missing requests.}
We repeat the comparisons by resampling days, and by clustering exact
query text (target paper for scholar) across runs. The latter checks
repeated targets, which day resampling alone does not address.
We also restrict the data to query-runs with no account-side failure in
any main engine. Of the 180 pairs whose primary adjusted intervals
exclude zero, 169 also exclude zero under both day resampling and this
matched-support check.

Table~\ref{tab:ci} shows the effect of matching, which retains 4,048 of
the 12,313 query-runs that have per-query files. Claude search moves
from 51.4 to 52.6. The matched order has $\tau_b=.91$ against
Table~\ref{tab:results}, with Keenable and Exa still first and second.
If one engine's excluded requests instead score zero or at the ceiling,
Claude search can take any rank from 3 to 20, TinyFish from 11 to 20,
Kagi from 10 to 16 and ChatGPT search from 9 to 15. Missing requests
therefore limit the rank claims for these four engines.

The published per-run scores, which Figure~\ref{fig:weekly} uses, count
account-side failures on news and rare as zero until 28 October and
exclude them after that date. Under the first rule, Claude
search scores 45.1 instead of 51.3 in the main window, and no other
engine moves by more than 0.9 points. Legal sampling and docket matching
changed on 2--3 November. Mean legal recall over the main engines is .54
in the week of 26 October and .69 in the week of 2 November, so the last
plotted week is not fully comparable with the earlier weeks.

\paragraph{Normalization, weights and timing.}
Removing an engine's own results from the ceiling changes its overall
share by at most 0.8 points. Dropping any one task preserves the leader.
The Keenable--Exa gap then ranges from 1.1 points (without scholar) to
6.2 points (without finance).

Among the 15 engines present in all ten plotted weeks, adjacent
rankings have $\tau_b=.85$--.94. In the first eight weeks, fixing the
news pool to those 15 changes no sampled weekly order. Restricting news comparisons to requests sent
within five minutes of the first engine retains 96\% of scored pairs,
leaves the order unchanged and moves no mean \ndcg by more than .010.
These checks address changing engine participation and dispatch lag.

We use stored identifier hits and 2,000 paired run-bootstrap resamples.

Body-keyword recall is .154 lower than title recall for Keenable and .802
lower for ChatGPT search. On body keywords, Keenable leads its realtime
mode by .012, Kagi by .048, Exa by .199 and ChatGPT search by .644. The
95\% intervals of all these paired differences exclude zero. They use
common papers, unlike the available-case means in

\paragraph{Audit protocol.}
The 200 queries in Section~\ref{sec:validation} come from runs of 17--29
October with at least 19 engines, one day past the main window. Each
model receives the production system prompt, the query profile, the URL,
the title and the snippet at temperature 0 with high reasoning effort.
Claude Opus 5.5 refuses the six results of one rare query, so all
numbers use the other 1,194. $\kappa$ and Exact use the consensus rounded
to a grade, and $\rho$ uses the mean. The 95\% interval of GPT-6 Luna's
$\kappa$ from a query bootstrap is .87--.91, which overlaps the
intervals of the other models. Pairwise $\kappa$ is .86--.92. The new
GPT-6 Luna grades agree with the stored production grades at .92, with
83\% identical, so repeated runs of one judge already differ.

\paragraph{Literal quotes.}
Of 1,200 rare query-runs, 504 contain quotes. On unquoted queries,
Exa, Perplexity and Brave (LLM ctx) lead, and Keenable is fourth.
Replacing the rare score with its unquoted-only value gives overall
$\tau_b=.96$ and a 3.2-point Keenable lead over Exa. Literal phrase
matching therefore affects the rare ranking even when the overall order
changes little. These checks use LLM judgments, not human labels.

\section{Finance Matching and Checks}
\label{app:finance}

\paragraph{Matching rules.}
A scale word fixes a money figure's scale. Bare figures,
including parenthesized losses, can mean thousands or millions only when
the preceding 200 characters contain a currency or financial cue. Years,
percentages and multiples do not qualify. Diluted EPS also needs
``EPS'', ``per share'' or ``earnings per''. Money gets no LLM backstop.
Other fields can receive an upgrade, never a revoked hit. The full rules
are in \path{src/needle/finance/canon.py}.

\paragraph{Why the narrow money band?}
An LLM audit of 399 results from production runs checks company, period
and line item.
Money-hit precision without table reading is .93 at the 0.1\% band and
.88 at 2\%: the wider band admits more wrong periods and related line
items. Money backstop upgrades have precision .36, which motivates
excluding them. These are model judgments, not human gold labels.

\paragraph{Fresh sample.}
The fresh sample has 307 new queries (146 money, 161 other), tested on
17 engines. An LLM checks the first matching result for 335
table-reading hits, 100 exact-band money hits and 50 other-field hits,
using at least the full 2,000-character input. Exact-band precision is .93, as in the production audit.
Of 335 table-reading hits, 235 confirm the correct figure and period
(.70), 95 omit period labels and five contradict the answer.
Confirmation rates differ by engine: for
example, 13/43 for Firecrawl and 42/44 for Exa. Pooled precision cannot
establish each engine's error rate.

\paragraph{Effect on reported ranks.}
Discounting each engine's main-window table-reading hits by its
unconfirmed fraction in the fresh sample lowers finance recall by up to
6.0 points. Dropping table reading entirely lowers finance recall by
0.1--7.5 points, with finance $\tau_b=.84$. In both checks, the overall
order has $\tau_b=.98$ against Table~\ref{tab:results} and overall ranks
1--10 stay fixed. The check bounds one scoring choice,
not all matcher error. The fresh sample has more money queries than
production and lacks the non-money backstop, so it cannot replace the
main table.
