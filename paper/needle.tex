\begin{abstract}
\needle is a live benchmark of web search APIs for AI agents. Agent
benchmarks rarely test the search API alone; \needle scores what the API
returns to the agent: titles, URLs and snippets. Hourly and daily runs
draw new queries from public sources for news, finance, papers and law,
plus a fixed stream of rare-word queries, and compare each API with the
best results any tested API found. Over eight weeks we test 26 API
settings (engines) from 20 vendors. On 12.4k shared
query-runs, paired tests order 178 of 210 engine pairs. Title lookups
hide large gaps: 23 engines find a paper from its title at recall@10
.71--.98, but from body keywords at only .08--.72. These results provide
evidence that API comparisons should also test queries built from a
paper's body.
\end{abstract}

\section{Introduction}

An AI agent may need the paper behind a detail it read elsewhere, such
as the query ``gap rent regularity'' (Table~\ref{tab:examples}), whose
words are absent from the paper's title and abstract. A web search API
decides which sources the agent can inspect, and shows only a title, URL
and snippet before the agent opens a page.

Testing the API alone is hard. The live web has no fixed corpus or
complete relevance labels; fixed test sets go stale and can leak into
training data \citep{sainz2023trouble,balloccu2024leak}; and a score
must use what the API returns, not the page behind it. End-to-end agent
benchmarks do not isolate the API (Section~\ref{sec:related}).

\needle tests this step directly: one query in, up to $k$ results out,
scored on the evidence returned to the agent, for five tasks with new
queries each run. Scorers compare each engine with a pooled ceiling: the
best results any tested engine found. Registry facts and rare queries can
repeat, and all judge checks use LLMs, not humans. Our claims:
\begin{itemize}[nosep,leftmargin=1.2em]
\item Paired tests order 178 of 210 pairs of the 21 main engines on
  12.4k shared query-runs; 32 pairs stay unresolved
  (Section~\ref{sec:results}, Table~\ref{tab:results}).
\item Title lookups hide large gaps: 23 of 26 engines reach scholar
  recall@10 .71--.98 from titles but .08--.72 from body keywords
  (Section~\ref{sec:results}, Figure~\ref{fig:scholar}).
\item Weekly ranks are stable but not fixed: adjacent weekly rankings
  agree at Kendall's $\tau_b$ .81--.94 (Section~\ref{sec:results},
  Figure~\ref{fig:weekly}).
\end{itemize}

\section{Related Work}
\label{sec:related}

\textbf{Live and API benchmarks.} LiveBench and LiveSearchBench draw new
items from dated sources but score model answers
\citep{white2025livebench,zhou2026livesearchbench}; \needle scores the
search results behind such answers. BrowseComp scores agents end to end
\citep{wei2025browsecomp}; FreshStack and BrowseComp-Plus fix the corpus
to isolate retrieval \citep{thakur2025freshstack,chen2026browsecompplus},
while \needle keeps the live web. API comparisons use static questions
under one agent \citep{selvam2026search,aa2026searchindex}, and web
engine audits use fixed query sets
\citep{lewandowski2015evaluating,kirsten2026characterizing}; \needle
draws new queries each run and scores the API without an agent.

\textbf{Scorers and tasks.} LLM assessors and simulated known-item queries
can reproduce system rankings
\citep{thomas2024llms,upadhyay2025largescale,azzopardi2007simulated,he2025totelicitation};
\needle uses both and checks its judge against raters from other vendors.
Domain benchmarks cover literature, caselaw and finance search on fixed
sets \citep{ajith2024litsearch,hou2025clerc,hu2026finsearchcomp}; \needle
runs these tasks on new queries each day. Full text helps retrieval beyond
abstracts \citep{lin2009fulltext}; our body queries test that gap on live
APIs.

\section{The Benchmark}
\label{sec:bench}

An \emph{engine} is an API at one setting. We test 26 engines from 20
vendors, including five mode variants. A \emph{query-run} is one query issued in one run.
Appendix~\ref{app:examples} gives the API settings and data sources.

\subsection{Queries}

Table~\ref{tab:protocol} summarizes the run schedule and scoring metrics.

\textbf{News.} Each hour an LLM writes 20 event queries from news feeds
and Google Trends, rejecting evergreen items.

\textbf{Finance.} Queries ask for company facts from Wikidata
\citep{vrandecic2014wikidata} and GLEIF, quarterly 10-Q figures from SEC
XBRL, or filings by description.

\textbf{Scholar.} Each recent arXiv or Europe PMC \citep{europepmc2015}
paper yields four paired known-item queries \citep{azzopardi2007simulated}:
its normalized \emph{title}; \emph{body keywords} for a detail absent from
title and abstract; a \emph{body question} about that detail; and a
\emph{tip-of-tongue} description \citep{arguello2021tot} without names or
exact values. All four must pass the filters.

\textbf{Legal.} CourtListener opinions yield caption queries; eCFR
sections yield queries based on verbatim spans. Filters reject citation
leaks.

\textbf{Rare.} We sample a fixed public stream of English agent queries
containing rare words \citep{ning2026agentic,li2026openresearcher,zhou2026lrat}.
Table~\ref{tab:examples} gives query examples; Appendix~\ref{app:leak}
gives the filters.

At least half of legal queries and finance money and filing queries carry
quotes, \texttt{site:}, \texttt{after:} or \texttt{before:}. The client maps
operators to native filters where available.

\subsection{Scores}
\label{sec:scoring}

\textbf{News and rare.} GPT-6 rates each distinct result from 0 to 4 using
a shared query profile, with checks for relevance, coverage, freshness and
literal operator compliance. The scale adapts the Needs Met levels of
\citet{google2025sqrg}. Ratings 0--4 map to gains
$g=\{0,0,.117,.667,1\}$, putting high weight on strong results
\citep{kanoulas2009empirical}. Snippets have a 2,000-character cap.

For each query, the \emph{ceiling} keeps the best rating per normalized
URL across all engines, variants included, and sorts these ratings
\citep{sparckjones1975pool,zobel1998reliable}. With $r_i$ the rating at
rank $i$, we compute \ndcg \citep{jarvelin2002cumulated} as
\begin{align*}
\mathrm{DCG}_e(q)&=\sum_{i=1}^{5}\frac{g(r_i)}{\log_2(i+1)},\\
\mathrm{nDCG}_e(q)&=\frac{\mathrm{DCG}_e(q)}{\mathrm{IDCG}(q)}.
\end{align*}
IDCG is the DCG of the top five pooled ratings. Missing ranks contribute
zero. Repeated normalized URLs receive zero gain except on
\texttt{site:} queries.\footnote{The pool still keeps each URL once, so
this exception can yield \ndcg above 1. The exception affects 3 of 1,748 rare
\texttt{site:} engine--query pairs in the main window.} We drop a query-run
from all engines if any judgment fails or no result reaches rating 2.
The task score is the mean over retained query-runs; the judged ceiling
has mean 1.

For example, A returns ratings 4 and 2; B returns 3 and 4, with the
4-rated URL shared. The pool contains 4, 3, 2, so
$\mathrm{IDCG}=1+.667/\log_2 3+.117/2=1.479$.
A scores .73 and B .88: the denominator uses the shared pool, not each
engine's own best ordering.

\textbf{Scholar, legal and finance.} Recall@$k$ counts queries with a
matching result in the top $k$. Scholar matches arXiv ids, DOIs and PMIDs;
legal matches citations, dockets and identifiers in URLs and snippets.
Caselaw recall measures case identity, not necessarily the opinion page.
Finance checks whether the snippets contain the answer, with a 0.1\%
money band and a 15\% headcount band. The matcher reads table figures and
parenthesized losses. An LLM may upgrade a non-money miss, but cannot
revoke a hit; a failed backstop judgment excludes an engine's query only
if no result matches. The ceiling is a hit by any engine.
Appendix~\ref{app:finance} checks matcher error.

\subsection{Overall share and failures}
\label{sec:agg}

For task metric $M_t$, an engine's overall share is
\[
S(e)=\frac{1}{5}\sum_{t=1}^{5}
\frac{M_t(e)}{M_t(\mathrm{ceiling})}.
\]
The tasks have equal weight. The ceiling is the best the tested engines
found, not the best the web contains.

Table~\ref{tab:results} uses dashboard scores from the 276 runs in which
all 21 main engines took part. On finance, scholar and legal, we exclude
account-side failures (our quota, rate limit, login or credit); other
failures score zero. On news and rare, every failure in this window scores
zero. These exclusions remove up to 28\% of an engine's query-runs.
\paragraph{Comparing two engines.}
Query difficulty varies widely and affects all engines alike, so
individual intervals can overlap even when one engine beats the other on
the same queries. We therefore
estimate the difference $S(a)-S(b)$ on shared runs. Within each task, we sample whole runs
with replacement 2,000 times, drawing the same runs for every engine
\citep{efron1993bootstrap}. Each sample preserves within-run dependence
and each engine's exclusions; we recompute query-weighted task and
ceiling means, then overall shares. We use the bootstrap standard error
to form a normal-approximation interval for each difference. Bonferroni
correction accounts for testing all $\binom{21}{2}=210$ pairs at once,
at a 5\% familywise level \citep{carterette2012multiple}. An interval that excludes zero supports
ordering that pair under these scoring rules. The intervals measure
sampling uncertainty, not scorer error. Appendix~\ref{app:checks} gives
the interval formula and checks other sampling units and failure policies.

\subsection{Judge validation}
\label{sec:validation}

We sample 100 news and 100 rare queries, with six distinct top-five URLs
per query (1,200 results). Two Claude Opus 5.5 raters, Gemini 4 Argon and
Grok 4.7 grade these with engine names hidden and a common written
guideline. Claude raters also see the first 3,000 page characters.
The Claude raters agree at quadratic-weighted $\kappa=.94$
\citep{cohen1968weighted}; Gemini and Grok agree with their consensus at
.92 and .90. Agreement with the production judge is .77--.79
(Table~\ref{tab:raters}). A separate snippet-only pass on 400 items finds
that adding page text changes 25\% of grades.

To test rankings on the same evidence as production, Gemini and Grok also
grade 100 complete query pools (50 per task): 5,698 unique results from
all 21 engines, using snippets only. Each gives engine-rank Spearman .94
against the production judge (95\% intervals .89--.97 and .87--.96).
All three retain the same top five in different orders; none separates
Keenable from Exa on this sample. These checks measure model agreement,
not human validation. Appendix~\ref{app:validation} gives the audit
protocol and checks sensitivity to evidence length and literal quotes.

\section{Results}
\label{sec:results}

\paragraph{The data support most pairwise rankings, not every rank.}
The adjusted score-difference intervals exclude zero for 178 of 210
engine pairs. We cannot reliably order the remaining 32 pairs from this
sample; an unresolved pair does not mean equal scores.
The overall lead also depends on the task mix: scholar contributes 3.7
points of Keenable's 4.7-point lead over Exa. Without scholar, the lead
is 1.2 points (Appendix~\ref{app:checks}).

\paragraph{Body queries expose gaps that title queries hide.}
Over 31 scholar runs, 23 of 26 engines reach recall@10 .71--.98
from titles. The same 23 span .08--.72 on body keywords
(Figure~\ref{fig:scholar}; Table~\ref{tab:buckets}). Keenable leads at
.72, followed by its realtime mode (.71) and Kagi (.67).
Appendix~\ref{app:scholarpaired} gives paired intervals on common papers.

\paragraph{Weekly ranks are stable, not fixed.}
Adjacent weekly rankings agree at Kendall's $\tau_b$ \citep{kendall1945ties}
.81--.94. Keenable leads all eight weeks, but lower ranks change
(Figure~\ref{fig:weekly}). Appendix~\ref{app:checks} checks changes in
the engine pool, account failures and dispatch times.

\section*{Limitations}

\paragraph{Conflict of interest.}
The authors' organization builds an evaluated engine. The code, prompts,
clients and per-query outputs are public so readers can audit the claims.
All engines receive the same queries, snippet cap, request pacing and
judge; each keeps one setting throughout the main window. We cannot tell
whether a vendor changed its index for the benchmark or for other reasons.

\paragraph{Evidence and judge.}
Scores measure the API response, not the fetched page. Short snippets can
hide relevant content \citep{turpin2009summaries,kazai2022less}, and identifier matching can miss a target without
its id. On 400 sampled results, page text changes 25\% of grades. News and
rare depend on one judge; all audit raters are LLMs, and none provides
human validation, which LLM labels cannot replace
\citep{faggioli2023perspectives,clarke2025llmbased}. Shared rules can cause
shared errors. Query-term stuffing can fool judges \citep{alaofi2024fooled};
vendor and model biases can affect scores
\citep{balog2025rankers,soboroff2025dont}. The judge shares a vendor with
ChatGPT search, and some audit raters share one with Claude search; LLM
evaluators can favor their own outputs \citep{panickssery2024self}.

\paragraph{Matcher error.}
Finance table figures can match the wrong period when snippets omit column
headers. In a fresh LLM audit, 5 of 335 table-reading hits contradict the
answer; 95 show the right figure without a period label, which the
snippet alone cannot confirm. The pooled audit cannot show each engine's
error rate. Caselaw recall credits pages about the case,
not just the opinion. Appendix~\ref{app:finance} gives the finance checks.

\paragraph{Coverage and weights.}
Queries are English and US-centric. Equal task weights do not estimate
agent traffic, and the lead depends strongly on scholar. Default API tiers
need not be each vendor's best. ChatGPT and Claude search return sources
through answer-generating tools, so their quality scores are comparable
but their latency and cost are not. The ceiling depends on the engine
pool \citep{buckley2007bias}; compare shares within a common window.

\paragraph{Failures and timing.}
Excluding account-side failures assumes those requests would score like
the rest. Without that assumption, several middle ranks remain uncertain.
News and rare also count our credit lapses as zeros in the main window.
Engines process queries at different speeds, so slow engines see news
later. A five-minute dispatch filter leaves the news order unchanged.
Vendor redirect links can break URL matching.

\paragraph{Repetition and reproducibility.}
Registry facts and the fixed rare stream can repeat. Public sources and
queries permit tuning or special handling of benchmark traffic. The studied
runs archive queries, reference answers, results and judgments, but lack
API publication dates and each run's code revision. Stored ratings reproduce the tables;
re-judging cannot exactly reproduce the inputs. Appendix~\ref{app:examples}
gives the source terms.

\section{Query Filters}
\label{app:leak}

Scholar samples five domains (computer, physical, life, social and health
sciences) and three age bands (7 days, 30 days, 1 year), targeting seven
accepted papers per cell. Each paper must pass
all four filters:
\begin{itemize}[nosep,leftmargin=1.2em]
\item \textbf{Title:} at least four words, plus a digit, acronym,
  hyphenated term or five content tokens.
\item \textbf{Body keywords:} at least three words and two content
  tokens absent from title and abstract.
\item \textbf{Body question:} at least eight words and the same novelty
  test as body keywords.
\item \textbf{Tip-of-tongue:} at least twelve words; no quotes, decimal,
  five-digit number or coined title/abstract term; at most two content
  tokens shared with the title.
\end{itemize}
An instrumented run accepts 323 of 572 candidate papers (56\%).
The effect of rejecting other papers on engine order is untested.

News draws from 124 feeds and Google Trends RSS for 52 US geographies;
prompts reject evergreen items and request two-to-six-word event queries.
Legal captions come from 14 federal courts on CourtListener. CFR queries
contain one verbatim two-to-eight-word span but no citation or target
section number. Only the quoted variant retains quotation marks.
Rare queries must pass fastText English language ID
\citep{joulin2017bag,joulin2016fasttextzip} and contain a word split into
at least five BERT WordPieces \citep{wu2016gnmt,devlin2019bert}.

\paragraph{Paired intervals.}
The main window has 12 scholar, 232 news, 10 finance, 12 rare and 10 legal
runs. For pair $(a,b)$, let $\widehat{\Delta}_{ab}=S(a)-S(b)$ and let
$s_{ab}$ be the standard deviation of its 2,000 bootstrap differences.
The adjusted interval is
\[
\widehat{\Delta}_{ab}\ \pm\ 3.683\,s_{ab}.
\]
The interval is a normal approximation, not a percentile bootstrap interval.
The implemented critical value is slightly more conservative than 3.675,
the two-sided Bonferroni value for 210 comparisons at familywise level
.05. Individual engine intervals in Table~\ref{tab:results} instead use
the 2.5th and 97.5th bootstrap percentiles. Their overlap is not a test
of the difference between two engines.

\paragraph{Dependence and missing requests.}
We repeat the comparisons by resampling days, and by clustering exact
query text (target paper for scholar) across runs. The latter checks

\section{Judge Sensitivity Checks}
\label{app:validation}

\paragraph{Audit protocol.}
The 200 queries in Section~\ref{sec:validation} come from 17--29 October
runs with at least 19 engines. Each Claude rater uses a separate random
order in 24 sessions of 50 items; Gemini and Grok grade one item per call
at temperature 0. All use the same written guideline. Raters assign mean
grades of 1.87--1.97 versus the production judge's 1.60, so agreement does
not imply identical grade calibration.

\paragraph{Evidence length.}
The staged snippet-versus-page check changes 25\% of 400 grades
(95\% interval 21--29\%), but the mean grade change is only +.05
[$-.01$, +.11]. Positive and negative changes can cancel in the mean.

On 803 news results from eight queries, a Claude Opus 5.5 judge grades both
full snippets and versions capped at 200 characters. The resulting engine
orders agree at $\tau_b=.73$ (95\% interval .40--.84); mean absolute share
change is .084. Exa and Keenable lose, while Bing (SearchAPI) and Google (Serper) gain.
The sample does not distinguish the top two at either length.
Snippet length is thus part of the measured API quality, not a controlled
property of the underlying page.

\paragraph{Literal quotes.}
Of 1,200 rare query-runs, 504 contain quotes. On unquoted queries,
Exa, Perplexity and Brave (LLM ctx) lead; Keenable is fourth. Replacing
the rare score with its unquoted-only value gives overall $\tau_b=.96$
and a 3.3-point Keenable lead over Exa. Literal phrase matching therefore
affects the rare ranking even when the overall order changes little.
These checks use LLM judgments, not human labels.

\section{Finance Matching and Checks}
\label{app:finance}

\paragraph{Matching rules.}
Money must fall within 0.1\% of the reference value; headcounts within
15\%. A scale word fixes a money figure's scale. Bare figures, including
parenthesized losses, can mean thousands or millions only when the
preceding 200 characters contain a currency or financial cue. Years,
percentages and multiples do not qualify. Diluted EPS also needs
``EPS'', ``per share'' or ``earnings per''. Money gets no LLM backstop;
other fields can receive an upgrade, never a revoked hit. The full rules
are in \path{src/needle/finance/canon.py}.

\paragraph{Why the narrow money band?}
An LLM audit of 399 results checks company, period and line item.
Money-hit precision without table reading is .93 at the 0.1\% band and
.88 at 2\%: the wider band admits more wrong periods and related line
items. Money backstop upgrades have precision .36, which motivates
excluding them. These are model judgments, not human gold labels.

\paragraph{Unseen-query check.}
A separate sample has 307 unseen queries (146 money, 161 other), tested
on 17 engines. An LLM checks the first matching result for 335
table-reading hits, 100 exact-band money hits and 50 other-field hits,
using at least the full 2,000-character input. Exact-band precision is .93.
Of 335 table-reading hits, 235 confirm the correct figure and period
(.70; 95\% Wilson interval .65--.75; \citealp{wilson1927probable}),
95 omit period labels and five contradict the answer. Counting unresolved
hits as wrong gives precision .70; counting only contradictions gives .99.
Confirmation rates differ by engine: for example, 13/43 for Firecrawl
and 42/44 for Exa. Pooled precision cannot establish each engine's error rate.

\paragraph{Effect on reported ranks.}
Discounting each engine's main-window table-reading hits by its fresh
unconfirmed fraction lowers finance recall by up to 6.0 points; overall
ranks 1--10 stay fixed. Dropping table reading entirely lowers finance
recall by 0.1--7.5 points, with finance $\tau_b=.84$ and overall .97;
overall ranks 1--3 stay fixed. The check bounds one scoring choice, not all
matcher error. The fresh sample has more money queries than production
and lacks the non-money backstop, so it cannot replace the main table.
